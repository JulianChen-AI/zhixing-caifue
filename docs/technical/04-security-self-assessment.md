# 安全自评报告

> 适用版本：`voice-bank`，分支 `feat/text-mode-optional-mic-v2`，提交 `299f495`（2026-11-01，含 Qwen 后台委托模式）。代码位置相对于 `voice-bank/`。
> 本系统是竞赛演示原型：账户、资金、联系人、产品均为合成数据，认证为演示验证码，未接入真实银行、支付通道或身份系统。控制措施的完整说明见 [安全设计文档](03-security-design.md)，本文只做两件事：说明权限分级是怎样实现的，列出目前已知的风险。

## 1. 自评结论

| 维度 | 自评 | 说明 |
|---|---|---|
| 模型越权执行 | 已控制 | 模型输出只是“提议”；确认要引用当前摘要令牌，认证只接受页面卡片入口，模型工具定义中没有认证操作 |
| 授权粒度 | 已控制 | 每个任务、每个摘要令牌单独确认；改任一字段即作废确认与认证；一轮确认不能授权下一步 |
| 结果真实性 | 部分控制 | 后台状态是唯一事实来源，监督与核对会更正错误播报；但流式语音存在时差，错误可能在被拦截前已被听到 |
| 身份与认证 | 演示级 | 固定演示验证码；本地访问有演示身份兜底；不具备生产强认证 |
| 平台加固 | 未完成 | 缺少 CSP 等安全响应头、速率限制、静态加密、防篡改审计 |

结论：**在“模型不能放行资金动作”这一核心目标上，控制由确定性代码实现并有单元测试覆盖；平台层与身份层仍是演示级，正式上线前必须补齐第 3 节列出的高、中风险项。**

## 2. 权限分级实现说明

权限从两个方向分级：**谁在调用**（调用方）和**做的是什么业务**（操作等级）。一次请求能否生效，取决于两者的交集，并由服务端统一判定，前端或模型的声明都不算数。

### 2.1 调用方分级

服务端按请求进入的入口区分调用方。入口由 `POST /api/bank` 的请求体字段决定，Zod 严格模式保证一次只能带一种（`app/api/bank/route.ts:41`），来源标记 `source` 由服务端写入，客户端不能自行指定。

| 调用方 | 入口 | 可以做 | 不能做 | 代码 |
|---|---|---|---|---|
| 用户（页面卡片） | `action` | 选择、编辑、确认、**认证**、取消、推进沙箱结算 | 绕过摘要令牌或认证令牌 | `app/api/bank/route.ts:73` 把卡片操作标为 `source: 'card'` |
| 实时语音模型 Qwen Omni | `tool`（`bank_plan` / `bank_function` / `bank_request`） | 查询、建草稿、补字段、改口；在用户原话确实表示确认时提交确认 | **认证**；推进结算；无依据地填写字段 | `lib/bank/tool-action.ts` 统一映射为 `source: 'voice'` |
| 后台委托模型 Qwen Flash（可选） | `POST /api/bank/delegate` | 与实时语音模型相同的三种工具，每轮最多 6 次调用 | 同上；同一 `requestId` 重试时不再调用工具 | `lib/voice/delegation.ts`，仅在 `QWEN_DELEGATION=responses` 时启用 |
| 草稿修复模型 | `recovery` | 漏调用或工具报错后，补建一次草稿或查询 | 确认、认证、执行；同类写任务已存在时另建任务 | `lib/workflows/recovery.ts:22` |
| 后台观察模型 | `POST /api/bank/supervise` | 只读事实，返回“继续”或“附依据的暂停建议” | 任何写入 | 端点没有提交业务的路径 |
| 核对模型 | `POST /api/bank/review` | 在 `accept / repair / reject` 中选择；`repair` 只能提交一次受约束修正 | 确认、认证；降低字段依据标准 | 修正经 `dispatchAction`，与语音同一条护栏 |
| 文字指令 / 离线演示 | `command` | 确定性解析为与语音相同的操作 | 认证 | `lib/workflows/offline.ts` |
| 演示控制 | `action`：`load_scene` / `advance_clock` / `reset` | 加载演示场景、推进演示时钟（只结算已授权的延迟转账和已保存的目标存入） | 产生新的未授权业务 | `lib/demo/control.ts` |

所有调用方都经过同一个分派函数 `dispatchAction`（`lib/plans/dispatch.ts`）进入外层 Plan 与内层 Checklist，没有为某个模型单独开的“快速通道”。

### 2.2 业务操作分级

54 项用户功能按副作用分为五级。分级由 `isWrite` 与 `needsAuth`（`lib/workflows/adapters.ts:82-87`）确定，不由模型判断。

| 等级 | 含义 | 放行条件 | 典型功能 |
|---|---|---|---|
| L0 只读 | 查询、目录、指引，不改变状态 | 通过参数白名单即可执行 | 余额与流水、账单分析、产品对比；以及 TR04、TR05、CA03 等功能的 `list / get / query / status / guide` 动作 |
| L1 草稿 | 建立或修改未提交的任务 | 每个字段须有依据（2.3） | 所有写业务在确认前的状态 |
| L2 一般写入 | 改变用户数据，但不动资金、不动卡片状态 | 字段依据 + 摘要令牌 + 用户明确确认 | TR05 AA 收款、TR07 取消未执行转账、TR08 收款联系人、TR09 往来记录、BI03 账单分类、BI08 预算、SU02 / SU03 订阅登记与续费预警、IN01 目标储蓄（不开自动转存）、IN04 目标调整、IN05 风险测评、IN14 理财提醒 |
| L3 敏感写入 | 资金变动、代扣授权、卡片状态 | L2 全部条件 + **页面认证** + 执行前再次预检 | TR03 转账、TR04 定时转账、SU04 / SU06 取消与恢复代扣、IN01 开启自动转存、IN02 目标存取、IN08 申购、IN09 赎回、IN12 撤单、IN13 定投、CA03–CA09 卡片申请、额度、解除限制、冻结 / 解冻、挂失、补卡、绑定迁移 |
| L4 阻断 | 不允许自助完成 | 不放行，明确告知原因 | BI07、BI10、CA10、CA11、CA12（未接入，返回“未接入、没有执行”）；命中诈骗风险信号的转账；司法限制的卡；风险等级高于测评结果的产品；正式挂失后的临时解冻 |

### 2.3 放行链：从提议到执行

每一级都在前一级的基础上加条件，任一环节失败都停在当前状态，不会跳级。

```text
模型提议参数
  │  ① Zod 严格校验：未知字段（如 skipAuth、passed）直接拒绝
  ▼
草稿（L1）
  │  ② 字段依据核验：收款人、金额、账户、开关项必须能从用户本轮原话独立核出
  │     （确定性中文金额解析，逐分比较；含糊、多金额无改口词、重名无区分一律不保存）
  ▼
预检：余额、对象存在、风险信号、适当性、卡片状态
  │  ③ 生成 reviewToken（不可变摘要）
  ▼
待核对
  │  ④ 确认必须引用当前 reviewToken；语音确认还须通过 acknowledgesReview
  │     （疑问、修改、转折、否定的语句不算确认）—— lib/workflows/engine.ts:220-224
  │     任一字段被修改 → reviewToken / confirmedToken / verificationId 全部作废
  ▼
L2：执行          L3：生成 verificationId，进入待认证
                    │  ⑤ authenticate 只接受 source = card，否则 403
                    │     —— lib/workflows/engine.ts:236
                    │     核对 verificationId、confirmedToken 与 reviewToken 一致
                    ▼
                  ⑥ 执行前再次预检 → 执行 → 写回执与审计（同一条原子 UPDATE）
                    失败则回滚到执行前状态
```

并发与重放：每个写请求带 `requestId`（保存最近 64 个）和期望 `revision`；数据库更新带 `WHERE revision = ?`，不一致返回 409。委托模式下每次工具调用的 `requestId` 为“本轮 ID + 序号”，同一轮重试时整轮拒绝再调工具，只返回“请核对卡片”（`app/api/bank/delegate/route.ts`）。

## 3. 已知风险清单

等级：**高** = 上线前必须解决；**中** = 上线前应解决或有明确补偿措施；**低** = 可接受或仅影响演示。

| 编号 | 风险 | 等级 | 现状与已有缓解 | 处置建议 |
|---|---|---|---|---|
| R01 | 认证为固定演示验证码 | 高 | 验证码固定为 `123456`（`lib/workflows/engine.ts:238`、`lib/bank/engine.ts:172`），页面会提示该值；仅用于沙箱 | 接入机构强认证（设备绑定、生物识别、动态 OTP），服务端校验 |
| R02 | “仅卡片可认证”是入口隔离，不是密码学隔离 | 高 | 服务端按请求入口区分卡片与模型，模型的工具调用无法到达认证；但页面内被注入的脚本可以直接以卡片入口发请求 | 与 R01 一并解决：认证由独立认证服务完成，业务端只接受其签发的一次性凭证；配合 R04 |
| R03 | 本地访问的演示身份兜底 | 高 | `localhost / 127.0.0.1 / [::1]` 访问时得到 `local-demo` 身份（`lib/bank/server.ts:24,29`）；演示服务器只监听 loopback，外部经 Tailscale Serve 注入身份 | 生产构建移除兜底，或只在开发模式启用 |
| R04 | 缺少安全响应头 | 中 | 未配置 CSP、`X-Frame-Options`、`Permissions-Policy`；有 Origin 校验与 `SameSite=Strict` Cookie 防 CSRF | 增加 CSP（脚本同源、连接限定百炼域名）、禁止被嵌入、限制麦克风权限来源 |
| R05 | 无速率限制 | 中 | 有请求体积、文本长度、任务数量和超时上限；但写入和模型调用频率不受限，可被刷量并产生模型费用 | 按身份与 IP 限流，模型调用单独计额 |
| R06 | 字段依据与语音确认依赖客户端上报的转写 | 中 | `utterance` 由浏览器提交；伪造转写只能影响本人会话，且 L3 仍需卡片认证 | 生产环境由服务端直接接收语音转写，或对转写做服务端签名后再用于依据核验 |
| R07 | 流式播报时差 | 中 | 语音直接流式播放，后台观察发现问题后才暂停更正，错误内容可能已被听到；观察不保证识别全部语义漏办；卡片始终显示后台事实 | 对“已完成 / 已到账”类措辞增加确定性前置门槛（有回执才允许播出） |
| R08 | 临时冻结的认证顺序与业务规则不一致 | 中 | 代码中 CA06 临时冻结属于 L3，先认证后执行；采用稿 CM-C08 要求“先止损后补验” | 按采用稿调整 CA06 为先冻结、后补验，补充测试；解冻仍须认证 |
| R09 | 诈骗识别为关键词规则 | 中 | 命中“刷单、解冻费、安全账户、保证金、跑分、兼职返利”即阻断，不可口头绕过；但换种说法可能漏判 | 接入机构反欺诈评分、收款方风险名单，增加升级核验流程 |
| R10 | 新增收款联系人不需认证 | 低 | TR08 属于 L2，只需确认；向该联系人转账仍是 L3，需要认证 | 生产环境参照机构规则，将新增收款人提升为 L3 或设置冷静期 |
| R11 | 审计可截断、无防篡改 | 中 | 审计与业务状态在同一条 JSON 中原子保存，保留最近 100 条，任务日志 200 条 | 独立追加式审计存储，带哈希链或签名，按监管要求保存 |
| R12 | 数据未加密存储 | 中 | 会话状态存于演示服务器本地 SQLite（Wrangler 本地持久化），全部为合成数据 | 迁移到托管数据库并启用静态加密，敏感字段应用层加密 |
| R13 | 对话内容发送给第三方模型 | 中 | 用户原话、回复与精简后的业务事实发往阿里云百炼；验证码、`verificationId`、问卷原始答案、完整审计不发送；6 位以上数字在依据引文中脱敏 | 生产前完成数据处理协议、数据出境与个人信息影响评估，明确留存期限；法规对照和灰度方案见[安全设计文档第 10 节](03-security-design.md#10-隐私法规对照与灰度上线方案) |
| R14 | 后台委托模式的验证不足 | 中 | 默认关闭（`QWEN_DELEGATION=responses` 才启用）；后台模型与语音模型走同一护栏，每轮最多 6 次工具调用，25 秒超时，已提交后失败返回“结果待核对”而非可重试错误；只有单元测试 | 启用前补浏览器端到端与真实模型回归，统计误调用与超时率 |
| R15 | 外部数据的提示注入 | 低（当前） | 进入模型的只有内置合成数据，外部账单导入（BI07）未接入；“导入字段注入隔离”检查单已定义未实现 | 接入外部数据前实现字段隔离与输出白名单 |
| R16 | 演示控制可推进时钟、重置场景 | 低 | 仅页面入口可调用；推进时钟只结算已授权的延迟转账和已保存的目标存入，各一次；有重放校验 | 生产构建移除演示控制入口 |
| R17 | 规则目录落地不完整 | 低 | 62 份业务检查单中仅 2 份标为 `demo-ready`，其余作为规则依据；54 项功能中 49 项有沙箱适配器，5 项明确不可用 | 按上线范围逐份实现并补测试 |
| R18 | 无 `Origin` 头的请求不做来源比对 | 低 | `checkOrigin` 只在带 `Origin` 时比对（`lib/bank/server.ts:17`）；浏览器跨站请求带不上 `SameSite=Strict` Cookie，非浏览器客户端只能操作自己的会话 | 生产环境对写接口强制要求 `Origin` 或 CSRF 令牌 |
| R19 | 未做真人验收与渗透测试 | 中 | 有合成音轨与真实模型的自动化记录；真人麦克风、手机回声、跨网质量与安全测试未进行 | 上线前完成真人语音验收、第三方渗透测试与模型红队测试 |
