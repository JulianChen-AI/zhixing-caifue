# 第一部分 · 我们要做什么（TL;DR）

**一句话**：用户的意图天然是跨业务的（"我女朋友快生日了"），银行的功能却是竖井的——鹅豆做那个**规划器**：把一句话拆成跨模块任务链，按正确顺序衔接执行，在每个写操作前停下来等你点头。

**三层联动模型**（由内到外）：

| 层 | 名称 | 内容 | 状态 |
|---|---|---|---|
| L3 | **产品内场景接力** | 账单→订阅解约、账单→理财定投、挂失→订阅迁移、宿舍账本→AA 收款等，收编为统一联动协议 | 已有功能级联动 → 本场景系统化为协议 |
| L4 | **条件触发与主动规划** | 用户规则引擎（"如果…就…"）+ 人生事件日历（发薪/开学/生日/毕业）驱动的主动任务链 | **本场景新建** |
| L5 | **跨 App 生态联动** | 金融任务链延伸到外部服务（美团订蛋糕/日历/桌面助手），带确认闸门出边界 | **本场景新建，旗舰案例演示** |

**旗舰案例：生日不翻车**——检测到女朋友生日临近 → 当月锁定 1000 元活期预算（理财目标罐）→ 提前 7 天主动问想法 → 生日前两天联动美团选好蛋糕鲜花 → 用户确认后唤起付款 → 支出自动回流账单标注"值得的花钱"。一条链跨理财/主动规划/跨 App/账单四个模块。

**评审点命中**：任务完成率 40%（多模块编排是任务链的最高形态）+ 安全合规 30%（确认交接/自动化分级/授权链是纲领第 3 节的完整答卷）+ 创新性 30%（L3-L5 全行业空白，详见差异化部分）。

**三条体验红线**（任何演示不可违反）：
1. **替我想着 ≠ 替我决定**——所有写操作停在确认闸门前，跨场景跳入写操作时确认重新过一次（XL-R3）
2. **主动 = 有依据 + 有节制**——每次主动触达带"为什么找你"，月度总量可控可关（XL-R5/R6）
3. **跨 App 只带到门口**——唤起+上下文+确认三件套，绝不"代客下单"（XL-R4）

**行为设计学锚点（v1.3，理论层见《行为设计学理论层》）**：本场景是双概念的**总枢纽**——
- **有限注意力**：鹅豆=**注意力代理人**（答辩话术："短视频的逻辑是抢占注意力，我们是注意力的外包商——用户每年花在我们产品上的注意力应少于 1 小时，但每一秒都值回票价"）；人生事件日历+显著性时机=在对的时刻出现一次；跑腿地图=把"检查计划"的注意力成本也压到最低。
- **过度自信**：规则引擎=**承诺机制总线**（规则创建即 Ulysses contract——清醒的你给冲动的你上保险，Save More Tomorrow 的引擎化）；What-if/事前验尸进入任务链模板（5.3-ext 深夜冲动守护="把决定从低带宽时刻移到高带宽时刻"）。
- **三条行为红线**（受益人/退出权/透明）+ **黑暗模式禁用清单**并入 XL-R 体系执行：默认项只许设为"保护你"、成长值断签不清零（不用损失厌恶制造焦虑性日活）、禁倒计时催单话术、关闭路径不劣于开通。

# 第二部分 · 官方四问对照表（纲领五）

## 2.0 附 · 四问总表

| 子任务 | ① 哪句话发起 | ② 需要的信息与授权 | ③ 依次完成哪些步骤 | ④ 哪些节点停下等确认 |
|---|---|---|---|---|
| 场景接力（对话内） | "帮我把这个僵尸订阅取消了，省下的钱存起来" | 各场景已有授权 + 跳转目标场景的写操作授权 | 意图理解（跨场景意图识别）→ 任务拆解（解约→定投两步）→ 上下文携带跳转 → 逐场景执行 | ① 跳入写操作场景时确认重新过一次 ② 链式第二步（定投建规则）单独确认 |
| 规则创建 | "工资到账就转 500 进小金库" | 规则引擎授权 + 涉及账户操作授权（硬编码落地，董小峰原则） | 规则条件解析 → 防呆校验（额度/冲突，XL-R9）→ 规则确认卡 → 入库待触发 | ① 规则创建时确认（含额度上限明示）② **首跑确认**（规则第一次触发时再次确认）③ 修改/删除随时可办 |
| 主动规划（事件驱动） | （系统触发）"你女朋友的生日还有 7 天" | 事件日历单独授权（XL-R7）+ 主动服务开关（XL-R5） | 事件检测 → 方案预生成（只读）→ 主动触达（带触发依据）→ 用户响应 → 进入任务链 | ① 事件日历建立时单独授权 ② 预生成方案的任何执行动作逐项确认 ③ 用户可"这次不用/以后别提醒" |
| 跨 App 联动 | "帮我订个蛋糕" | 跨 App 唤起授权 + 银行付款闸门 | 需求澄清（预算/口味/时间）→ 方案生成 → 唤起第三方官方页面（携带上下文）→ 用户在银行闸门完成付款 → 结果回流账单 | ① 唤起前展示方案确认 ② **付款必须过银行确认闸门**（不得承诺"已订好"）③ 第三方页面内操作归用户 |

**纲领第 1 节五环节在联动场景的映射**：意图理解（跨场景意图识别是本场景独有难点）→ 信息调用（跨场景数据引用需授权链校验，XL-R1）→ 任务规划（planner 拆解与排序，本场景核心）→ 结果解释（每步依据句+整条链的计划预览，XL-R6）→ 后续操作（链式下一步选项）。

# 第三部分 · 场景全景与需求依据

## 3.1 核心洞察（附件1 结论）

用户从来不说"我要转账"——用户说"我女朋友快生日了""这个月怎么又没钱了"。**每个真实意图背后都是一条跨业务任务链，而用户被迫自己当规划器**：自己拆解、自己切换、自己记住中间状态，断点随时发生。前五个场景把每个"环"做对了，本场景把"链"做出来。

## 3.2 七大痛点（附件1，按严重度）

P1 生活事件没有金融服务承接 ★5｜P2 跨页面/跨App操作链断裂 ★5｜P3 上下文反复重述 ★4｜P4 主动服务=打扰的信任危机 ★4｜P5 人生阶段切换金融服务断层 ★4｜P6 关系型事务社交成本 ★3｜P7 "知道但做不到"知行断裂 ★3

## 3.3 行业水位（附件2 结论）

Erica/Eno 把"主动洞察"（L1→L2）做成标配，Monzo 把"用户规则"做成标配——**但 L3 跨场景接力（AI 规划的多步任务链）、L4 事件驱动、L5 带确认链的跨 App 执行在全球银行业均无完整实践**。微众自身面客 Agent"很少、很初级"（董小峰内部口径）——本场景直接补主办方能力空位。

## 3.4 主动服务三原则（设计总约束，附件1 定性结论）

1. "替我想着"≠"替我决定"——预规划受欢迎，预执行被警惕
2. 主动的价值与频次成反比——总量控制与关闭权是信任前提
3. 可信的自动化是"看得见的规则"——每条自动化可查看、可暂停、可撤销

# 第五部分 · 核心能力设计（L4/L5 层新建）

## 5.1 统一联动协议（全场景的一等公民）

行业里有的是功能列表，没有一家把"场景间如何接力"当成一等公民（附件2 空位 1）。我们的协议四要素：

```
link_chain {
  link_id          -- 任务链唯一标识（留痕审计，XL-R11）
  trigger          -- 触发源：用户对话 / 用户规则 / 人生事件 / 数据信号
  steps[]          -- 步骤序列：每步 {场景, 意图, 所需授权, 确认级别}
  context_passed   -- 允许携带字段白名单（最小必要，XL-R1）
  confirmation_log -- 每个确认节点的记录：话术/用户响应/时间戳
  status           -- 进行中/已完成/已中断（中断须告知断点与手动继续路径，XL-R8）
}
```

**关键规则**：从只读场景（账单）跳入写操作场景（转账/解约/申购/挂失）时，确认闸门**重新过一次**——不因前序任何授权豁免（XL-R3）；确认话术必须包含"将要在哪个场景执行什么"。

## 5.2 规则引擎（L4 层，"看得见的自动化"）

**定位**：用户可建的"如果…就…"，信任地基（附件1 原则 3）；AI 自由规划建立在其上、而非取而代之。

**规则类型与默认护栏（XL-R2/XL-R9）**：

| 规则类型 | 示例 | 确认级别 | 默认硬上限 |
|---|---|---|---|
| 资金划转类 | 工资到账转 500 进小金库 | 创建确认+首跑确认，之后免逐次确认（董小峰：极低风险循环确认一次即可） | 单笔 ≤500、日累计 ≤1000（默认保守值，用户可调但调高超额需强认证） |
| 提醒类 | 房租日前 3 天提醒我 | 创建确认 | 频次防打扰（并入 XL-R5 月度总量） |
| 联动类 | 发现僵尸订阅就问我要不要取消 | 创建确认+每次执行确认（因含写操作入口） | — |
| 复合类 | 生日前 7 天锁预算+提醒我 | 创建确认+执行节点逐项确认 | 锁预算额度 ≤2000 |

**防呆设计**：冲突规则检测（两条规则同时触发→告知用户并执行优先级）；规则中心一页可见（全部规则/触发历史/暂停开关）；规则修改删除留痕。

## 5.3 人生事件日历（L4 层的触发源）

**概念**：银行按业务组织，我们按"用户的人生节拍"组织（附件2 空位 2）——开学/发薪/生日/纪念日/毕业/考试季，每个事件对应一条预置任务链模板。

**事件→任务链模板库（首批）**：

| 事件 | 预置任务链 | 涉及场景 |
|---|---|---|
| 生日/纪念日（旗舰） | 检测临近→锁预算→提前问想法→跨 App 选购→付款→账单标注 | 理财+主动规划+跨App+账单 |
| 发薪日（栗子） | 到账检测→执行划转规则→结余播报→还款日编排 | 转账+理财+账单+订阅 |
| 开学季（小知） | 生活费到账→预算分配建议→大额支出预警白名单 | 转账+账单 |
| 毕业（三人群共有） | 账单体系迁移（确认制）→订阅葬礼→学生价失效提醒→提额包 | 账单+订阅+卡片（接入路演第五幕） |
| 异常事件 | 异常扣款→分级提醒→一键冻结→迁移清单 | 账单+卡片（收编链） |
| **v1.2 扩展**：第一份工资/妈妈生日/生活费断供/异地见面/道歉急救/考试季/开学季/租房季/份子钱/深夜守护 | 见 5.5-ext 完整链与模板库扩展表 | —— |

**授权纪律（XL-R7）**：恋爱关系/生日/学业阶段属敏感推断，事件日历**单独授权**建立，不用于营销画像，可随时删除；每个事件可单独开关（"我女朋友的生日可以记，我妈的不用"）。

## 5.4 跨 App 生态联动（L5 层，旗舰能力）

**三件套原则（XL-R4）**：唤起 + 上下文携带 + 留好确认——银行 Agent 把用户带到第三方官方页面的正确位置，带着全部已确认的需求参数；最终下单付款由用户亲自完成。

**首批联动方向（董小峰会议待办）**：
1. **美团**（生日不翻车执行端）：蛋糕/鲜花选购——Demo 以小程序唤起+沙箱模拟，真实展业走官方开放能力；话术止于"已帮你选好这三款，确认后跳转付款"，禁"已帮你订好"
2. **Kimi 桌面助手**（分工范式）：银行侧管"金融任务链+确认闸门"，通用助手管"非金融操作面"（如把生日写进日历、给女朋友发提醒草稿）——答辩口径："开放协作而非闭门造车；金融的归银行，其他的归生态"
3. **远期（仅答辩弹药）**：把任务链能力封装成可被 OS 级 Agent 调用的意图接口（Apple App Intents 范式）——银行做能力提供方，不做 OS

## 5.5 旗舰案例：生日不翻车（完整任务链设计）

**人物**：阿澈（大四，对齐全局画像）。**触发**：事件日历中"女朋友生日 11 月 3 日"临近（T-7 天）。

```
T-7 天  鹅豆主动触达（主动服务授权内，带触发依据）:
        "下周二是小冉生日（你在 3 月让我记下的）。
         去年你当天才想起来，临时买花多花了 80。
         要不要今年我帮你安排？"
  ├─ [用户] "好啊，预算 300 以内"
  ├─ 步骤1（理财·目标罐）: 从活期锁定 300 到"生日预算"罐
  │    → 确认①: "锁 300 到生日罐，当天解锁。可以吗？"（写操作确认）
  ├─ 步骤2（方案预生成，只读）: 鹅豆生成方案卡:
  │    蛋糕（4 寸，~128）+ 花束（~99）+ 留 70 机动
  │    [依据句: 按你定的 300 预算；蛋糕花束为美团参考价，以实际为准]
  ├─ [确认②] 用户选定方案 → 计划入库，T-2 执行
  │
T-2 天  鹅豆: "后天就是啦，方案还作数吗？我选好了三家店"
  ├─ [确认③] 用户确认 → 唤起美团小程序（携带：品类/预算/送达时间地址）
  │    【跨 App 三件套：唤起+上下文+确认；话术:"选好点付款就跳过去"】
  ├─ 步骤3（付款·银行闸门）: 美团内下单 → 支付跳回银行确认闸门
  │    → 确认④: 付款 227（从生日罐扣，预算内）→ 完成
  └─ 步骤4（账单回流）: 支出自动标注"生日·值得的花钱"，
       联动账单场景年度叙事素材（"11 月你为小冉准备了生日，
       比去年早了两周"——AI 生成标识，BA-R11 同源纪律）
```

**一条链命中**：主动规划（T-7/T-2 两次触达，依据句随行）→ 理财锁预算 → 跨 App 唤起 → 银行付款闸门 → 账单回流叙事。**四次确认、零次越权**——这就是纲领第 2、3 节的完整答卷。

## 5.5-ext 旗舰案例集（v1.2 新增：三个完整任务链）

> 与「生日不翻车」同一配方：人生事件→跨模块接力→确认随行→情感落点。三个案例分别覆盖职场转折、亲情、窘迫守护三种情绪类型。

### 旗舰案例二：「第一份工资」（栗子，毕业幕核心戏）⭐

**触发**：检测到首笔"工资"类目收入（账单分类器，入职 1 个月内首次）。

```
7 月 12 日  鹅豆主动触达（事件驱动，带触发依据）:
        "栗子，这是你挣的第一笔钱。🎉
         想好怎么安排了吗？我有三个建议，都由你定。"
  ├─ 建议①（转账·亲情）: "给妈妈转 520？附言我帮你写了几条，你可以改"
  │    → 确认①: 金额+附言确认 → 走转账 TF-T01 确认闸门
  ├─ 建议②（理财·定投）: "每月 500 启动'工作第一年'计划？"
  │    → 确认②: 规则创建确认 + 首跑确认（XL-L02 两级）
  ├─ 建议③（节律编排）: 识别房租日/还款日 → 建提醒规则（确认③）
  └─ 收尾: "还剩 800 多——请自己吃顿好的，这个我不劝你存。"
       账单回流+年度叙事收录（AI 生成标识，口径依据句）:
       "7 月 12 日，你赚到了第一笔工资，你先想到了妈妈。"
```

**为什么必收**："这个我不劝你存"是路演级台词——有分寸的理财教育（不劝每一分都存，反而建立信任）；一条链跨转账/理财/规则引擎/账单四模块，且情感峰值最强。

### 旗舰案例三：「妈妈生日」（与女友版镜像双打）⭐

**触发**：事件日历"妈妈生日"临近（T-7）。**与生日不翻车同构不同解**——评委全是父母辈，这一幕是打给他们的。

```
T-7 天  鹅豆: "下周四是阿姨生日。去年你发了个 8.88 的红包。"
  ├─ 方案生成（只读，依据句：历史转账记录+"妈不爱收贵的"用户自述）:
  │    a) 转账 520 + 当天 19:00 视频电话提醒（联动日历）
  │    b) ⭐把家里宽带费绑到你卡上代扣，每月 69——
  │       "一次大的她会心疼，每月 69 她能跟邻居念叨你一年"
  │       （订阅场景·代父母管理代扣的反向场景；代扣协议建立需
  │        用户确认+父母侧知情说明，话术含"记得先跟家里说一声"）
  │    c) 鲜花蛋糕跨 App（复用生日不翻车链路）

       "这一年，你给家里花了 12 次心思。"
```

**为什么必收**：给爸妈花钱的正确方式不是一次大的，是**每个月都让他们感觉到你**——b 方案把"订阅/代扣"这个年轻人痛点场景反转成亲情工具，是六场景里唯一"代扣用于表达爱"的设计。

### 旗舰案例四：「生活费断供缓冲」（小知，窘迫感守护）⭐

**触发**：生活费转账节律中断（冷启动保护：观察满 2 个月节律后才启用；本月 15 号该到，20 号未到）。

```

         要不要我帮你看看小金库能撑几天？"
  ├─ 缓冲方案（只读计算，依据句）:
  │    小金库余额 ÷ 近三月日均必要支出 = 可撑 9 天;
  │    非必要支出临时清单（可选暂停项：视频会员/奶茶基金……）
  ├─ [确认①] 暂停项逐项确认（不替你停，只问"这个先停一周行吗"）
  ├─ 可选: "要我帮你拟一条跟妈开口的消息吗？"
```

**为什么必收**：窘迫感是大学生最真实的痛点（附件1 P1 的阴暗面）；"代拟不代发"把 Agent 的边界感做成泪点——它管的不是钱，是你的体面。

## 5.6 创新扩展（v1.1 新增）

> **取舍纪律**（不摊大饼）：①②进正文主线（撑起规划层差异化），⑤③进 Demo 演示，④并路演第五幕，⑥列候选不进 MVP。每个创新点均做过"挑刺预演"——不宣称技术新概念、不依赖拿不到的数据。

### ① 「鹅豆跑腿地图」· 任务链可视化（透明层）⭐主线

**概念**：每条 link_chain 渲染成一张"跑腿地图"——每个步骤是一个站点，每个确认闸门是一个"等你点头的岗亭"，鹅豆拿着小旗子站在当前位置；用户可放大看任意一步"为什么有这步、要用什么数据、下一步去哪"。

**为什么**：纲领第 4 节"讲清依据和不确定性"的最强具象化——全行业都在说"AI 可解释"，没有人把 **AI 的规划过程本身**做成可检视的产品界面。答辩金句："别的 Agent 让你信任它，我们的 Agent 把计划摊开让你检查。"

**合规**：纯呈现层创新，无新增数据风险；展示字段受 context_fields 白名单约束（XL-R1）。

### ② 「断点续接」· 鹅豆的挂念（可靠层）⭐主线

**概念**：任务链中断（用户未及时确认/第三方页面关闭）不作废——鹅豆**带着全部上下文等用户回来**："上周订蛋糕那件事，我停在付款那步，方案还留着，要继续吗？"跨会话、跨天的任务续接，断点状态完整保鲜。

**为什么**：真实 Agent 产品的能力空白——所有对话式产品都是"会话即生命周期"，链断即重来。本设计把 XL-L09/XL-R8 的容错机制升级为"**情感化的可靠**"：鹅豆不是没做成的工具，是"还替你记着"的伙伴，直接长进陪伴叙事。

**数据纪律**：断点链数据保留期 **30 天**，到期未续接自动清理并告知用户（"那件事我先帮你收起来了，想继续随时说"）；保留期内用户可一键清除（XL-R1 最小必要）。

### ③ 「链上后悔药」· 跨场景一键回滚（安全层，进 Demo）

**概念**：任务链级 undo——"刚才那条链我不想跑了"→ 一键回滚：刚建的规则暂停、刚锁的预算解锁、刚恢复的订阅还原（可逆窗口内）。每条链执行后生成**回滚卡**：列出这条链做过的 N 个动作，分层标注——**可逆**（规则/锁定/提醒设置）/ **不可逆**（已完成的对外付款）/ **补救路径**（已付款蛋糕→退款指引）。

**为什么**：撤回在单场景有人做（转账"可撤销转账"），**跨场景整条链的回滚没人做**——补偿事务（compensating transaction）思想在 C 端的产品化；它是安全合规主场的进攻版：不是"我们不出错"，是"**就算改主意也有退路**"。

**合规**：可逆/不可逆/补救三层如实标注，不承诺"什么都能撤"；回滚动作本身也留痕（XL-R11）。

### ④ 「你今年让鹅豆跑过的腿」· 年度任务链回顾（情感层，并路演第五幕）

**概念**：年度账单的联动版——"这一年你说了 47 句话，鹅豆跑成了 43 条链：帮你盯住 3 个僵尸订阅、没让你忘记小冉的生日、在 2 次异常扣款时替你站了岗。合计省下 6 小时、210 块。"审计留痕（XL-R11）直接变成年度情感资产与社交货币。

**为什么**：一石二鸟——成长陪伴叙事的年度高潮（与账单《你这一年的钱的故事》合并设计），同时完成**审计透明的产品化**：留痕不是合规负担，是用户爱看的年度回忆。全行业没人把 audit log 变成用户资产。

**口径纪律**："省下 210 块"类数字必须定义口径（如僵尸订阅年避免续费额，依据句标注"按取消时月费×剩余月份估算"）；分享前二次确认+脱敏预览（沿用 BA-R9）；AI 生成内容标识（账单 2-F2 同源）。

### ⑤ 「点头仪式」· 把确认闸门做成产品签名（交互层，进 Demo）

**概念**：每次确认不是冷冰冰的"确定/取消"——鹅豆举起小印章，用户语音说"好"或点一下，"咔哒"盖下去，印章飞向跑腿地图上的对应岗亭。年度回顾里集印："今年你盖了 43 个章，每一个都算数。"

**为什么**：确认闸门是监管要求（成本），全行业把它做轻做快藏起来；我们反着来**做重做成仪式**——合规动作情感化，是"知行合一"的微观落点（行之前必有知的确认）。"每一步你说了算"从口号变成用户记得住的瞬间。

**防打扰降级**：高风险操作保留完整仪式；低风险规则触发可设"静默模式"（用户自选，设置项留痕）——仪式感不拖慢高频操作。

### ⑥ 「多人协同链」· 宿舍/情侣共同任务链（社交层，P1 候选）

**概念**：任务链的多人版——毕业旅行基金：3 人各自授权、各自设规则（每人每月锁 100）、链自动汇总进度，**谁也看不到谁的流水，只见公共进度条**；到目标日鹅豆问全员"够 1800 了，谁来做攻略？"

**为什么是候选**：情感价值真实（关系型储蓄是空白），但依赖账单场景宿舍 AA 账本（BA-B13）+ 转账 AA 收款（TF-T05）联调，工作量大；多人授权链合规复杂度上台阶（任一成员退出时链如何降级需专门设计）。**列 P1 候选，作答辩弹药**——评委问"联动的边界在哪"时的"我们想过更远"证据。技术口径与账单 v1.7 对齐：共享账本+权限设计即可实现，不宣称联邦学习/隐私计算。

# 第六部分 · 架构与任务流

## 6.1 架构：规划层（planner）坐在五层之上

```
┌─────────────────────────────────────────┐
│  规划层 planner（本场景新增）              │
│  · 跨场景意图识别 → 任务拆解/排序          │
│  · 规则引擎（条件表驱动，硬编码执行）       │
│  · 事件日历（授权分级）                   │
│  · 联动协议注册表（link_chain 登记/留痕）  │
├─────────────────────────────────────────┤
│  确认交接总线：任何写操作步骤 → 强制过该    │
│  场景自己的确认闸门（不豁免、不合并）       │
├─────────────────────────────────────────┤
│  五场景业务模块（转账/理财/账单/订阅/卡片） │
│  —— 各自五层架构与红线原位生效             │
└─────────────────────────────────────────┘
```

**董小峰架构原则沿用**：planner 也是"员工"——规则触发由硬编码条件表执行，不由模型自由发挥；模型负责"理解与编排"，硬代码负责"授权与执行"。

## 6.2 联动协议关键流程（注册→执行→留痕）

1. **注册**：新联动链登记四要素（触发源/携带字段/确认节点/留痕格式）后方可上线
2. **执行**：planner 按 steps 序列推进；每进入新场景，校验该步授权（XL-R1）→ 过该场景确认闸门（XL-R3）→ 执行 → 记录 confirmation_log
3. **中断**：任一步失败/用户拒绝 → 链状态置"已中断"，鹅豆明确告知"已完成什么、卡在哪、你可以怎么手动继续"（XL-R8）
4. **留痕**：link_id 全程可审计，用户可查看"这条链替我做过什么"（XL-R11）

| XL-L09 | 断点续接·鹅豆的挂念（v1.1 升级，5.6②） | 链执行失败/被拒/超时未确认 | 断点状态保鲜（保留 30 天）→ 断点告知→手动继续路径→**跨会话主动挂念**："那件事我停在哪一步，要继续吗"→（可选）重新发起；到期未续接自动清理并告知 | 重新发起确认 |
| XL-L10 | 毕业迁移复合链 | 毕业事件 | 账单迁移（确认制）→订阅葬礼→提额包→阶段切换确认 | 逐环节确认（接入路演第五幕） |
| XL-L11 | 链上后悔药·跨场景回滚（v1.1 新增，5.6③） | "刚才那条链我不想跑了" | 回滚卡生成（动作清单+可逆/不可逆/补救三层标注）→ 用户勾选回滚范围 → 可逆动作逐场景补偿执行 → 全程留痕（XL-R11） | 回滚范围确认 |

## 6.4 数据模型（新增表，共享表沿用）

```sql
-- 规则引擎
automation_rules(rule_id, user_id, type, condition_json, action_json,
                 amount_cap, daily_cap, status,           -- active/paused/deleted
                 created_via, first_run_confirmed,         -- 首跑确认标记
                 last_fired_at, fire_count, version)       -- 修改留痕版本号
rule_fire_log(fire_id, rule_id, fired_at, trigger_snapshot_json,
              confirm_status, result)                      -- 每次触发留痕

-- 事件日历（敏感，XL-R7）
life_events(event_id, user_id, event_type, event_date, related_person_alias,
            consent_id, enabled, source)                   -- source: 用户录入/对话推断(需确认)
-- 注意: related_person 仅存别名，不存身份证号等直接标识

-- 联动链（XL-R11 审计）
link_chains(link_id, user_id, trigger_type, trigger_ref,
            steps_json, context_fields_json, status,
            created_at, completed_at, broken_at, break_reason,
            breakpoint_expire_at)          -- v1.1：断点保鲜 30 天，到期自动清理并告知（5.6②）
link_confirmations(link_id, step_no, scene, action, confirm_text,
                   user_response, confirmed_at)

-- v1.1 新增：链上后悔药（5.6③，XL-L11）
link_rollback_cards(link_id, actions_json,    -- 每动作: {scene, action, reversibility: reversible/irreversible/remediable, compensate_ref}
                    created_at, expires_at)   -- 可逆窗口（默认 24h，资金类即时不可回滚仅给补救路径）
rollback_log(rollback_id, link_id, scope_json, executed_steps_json, rolled_back_at)  -- 回滚也留痕（XL-R11）
```

共享表沿用：`transactions`/`audit_logs`/`category_dict`（账单中枢）；各场景写操作仍写各自业务表——本场景只新增"链"的元数据，不复制业务数据（最小必要，XL-R1）。

# 第七部分 · 合规红线（XL-R1 ~ XL-R12）

> 完整版见《附件3》。核心纪律一句话：**联动红线管"链"，场景红线管"环"**——链上每个环仍由所属场景的确认闸门与红线守护。

| # | 红线 | 一句话落点 |
|---|---|---|
| XL-R1 | 授权链不蔓延 | 每步独立校验授权；无授权跳转降级"带路不带数据" |
| XL-R2 | 自动化三级分级 | 只读建议/规则触发（首跑确认+可暂停+额度上限）/对外付款（每次确认或白名单） |
| XL-R3 | 确认闸门跨场景交接 | 跳入写操作场景确认重新过一次，话术含"将在哪执行什么" |
| XL-R4 | 跨 App 三件套 | 唤起+上下文+确认；不代客下单、不模拟登录、不承诺"已订好" |
| XL-R5 | 主动服务节制 | 与营销推送物理隔离；非安全类月度 ≤4 次（可调可关）；关闭路径不劣于开通 |
| XL-R6 | AI 规划透明化 | 每次主动带触发依据；计划预览"我打算分 N 步"；推测成分依据句标注 |
| XL-R7 | 事件日历敏感授权 | 恋爱/生日/学业单独授权，不做营销画像，可删 |
| XL-R8 | 中断责任话术 | "已完成什么、卡在哪、怎么手动继续"，不留沉默失败 |
| XL-R9 | 规则防呆防自伤 | 默认额度硬上限；冲突检测；修改删除留痕 |
| XL-R10 | 未成年人限制 | <18 不开放对外付款级自动化与事件日历；<14 监护人同意+只读建议 |
| XL-R11 | 联动留痕可审计 | link_id 全程记录，用户可查"这条链替我做过什么" |
| XL-R12 | 不夸大自动化 | 禁"AI 替你管钱"；统一口径"每一步你说了算"；跨 App 环节标注沙箱模拟 |

# 第八部分 · 演示剧本要点（接路演文档）

**主线**：旗舰案例生日不翻车（5.5）作为路演"跨场景联动"幕的完整演示——T-7 触达 → 锁预算 → T-2 方案 → 唤起美团（沙箱）→ 银行闸门付款 → 账单回流叙事。**演示节奏 3 分钟，四次确认全部现场呈现**——评委亲眼看到"AI 规划了很多，决定权一次没少"。

**v1.1 演示增强（5.6 三件套）**：
1. **全程在「鹅豆跑腿地图」上演示**（5.6①）——链的每一步点亮一个站点，四次确认=四个岗亭，评委看到的不是聊天记录，是"一条被规划、被检视、被执行的路径"（纲领第 2 节原话的视觉化）
2. **每次确认走「点头仪式」**（5.6⑤）——鹅豆举印章、用户说"好"、"咔哒"盖章飞向岗亭——把合规动作做成全场记忆点
3. **备用桥段二**：演示结束后现场"反悔"——「链上后悔药」（5.6③）一键回滚锁预算与规则，回滚卡三层标注（可逆/不可逆/补救）——回答"自动化出错/改主意怎么办"

**备用桥段一**（评委追问）：规则引擎现场建一条"工资到账转 500"→ 展示首跑确认 → 展示规则中心暂停——回答"自动化可信吗"。

**与路演总文档的衔接**：本场景是"一个人与一只鹅的四年"的针线——跨场景联动主场为**路演第五幕**（入职·知行合一总爆发）；毕业迁移（XL-L10）、年度任务链回顾《你今年让鹅豆跑过的腿》（5.6④，与账单年度叙事散文合并设计）已在排布口径内；**v1.2 新增案例（生日不翻车/第一份工资/妈妈生日/生活费断供缓冲）尚待与路演六幕结构正式排布对齐**（口径修正：原"生日不翻车（大二幕）"为误标——阿澈案例不占用小知四年幕次，拟以"番外篇/第五幕演示替换项"形式统筹），台词归属路演文档统筹。

# 第十部分 · 差异化对照与原创性声明

## 10.1 差异化对照

| 对象 | 它做到哪 | 我们的不同 |
|---|---|---|
| Erica / Eno | 主动洞察（L1-L2），洞察→行动靠用户手动 | 洞察直接进任务链，确认链完整（L3） |

| Operator/Rabbit R1 | 敢跨 App 代操作 | 无金融确认链的自动化在银行业不成立——我们的克制是合规护城河 |

## 10.2 原创性声明

- "统一联动协议"（link_chain 四要素登记制）、确认交接总线、自动化三级分级（含首跑确认）、人生事件日历的任务链模板库、生日不翻车全链设计——均为团队原创，经附件2 调研确认无同业完整实践
- **v1.1 新增原创点**：鹅豆跑腿地图（AI 规划过程可视化）、断点续接（跨会话任务链保鲜+断点保留期纪律）、链上后悔药（跨场景补偿回滚三层标注）、年度任务链回顾（审计留痕情感化）、点头仪式（确认闸门仪式化）——经附件2 调研确认未见同业完整实践；多人协同链（5.6⑥）为团队储备概念
- "生日不翻车"概念源自团队朋友圈调研文案（2026-10-14 发布并获真实用户反馈），本场景是其工程化落地
- 跨 App 三件套（唤起+上下文+确认）受订阅场景"分通道直达指引"（S-R15 降级实践）启发，属团队内部方法论迁移

## 10.3 数据与事实口径备忘

- Erica/Eno/Monzo-IFTTT/支小宝能力描述以公开资料为限，答辩不引用未经核实的具体交互量数据
- "全行业空白"的措辞限定为"经附件2 调研未见完整实践"，不说"全球唯一"
- 美团/Kimi 桌面助手联动在 Demo 中为沙箱模拟，演示须标注（XL-R12）
