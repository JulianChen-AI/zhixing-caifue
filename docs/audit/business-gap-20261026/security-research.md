## 2. 安全攻防实施方案 v2.0

这里核对的是设计要求与当前沙箱实现的差距，不是对真实银行系统的渗透测试。P2声明项不计入必须补代码的业务；尚未开放的导入、富文本、第三方唤起、公共账本也不能仅因缺对应护栏就认定当前已有可利用漏洞。

### 安全稿中需先裁定的冲突

1. D1低风险允许语音“好”直接确认，但E0写明任何写操作最终确认必须手动。需定一条一致规则，不能开发时自行择一，也不能用现在统一页面验证码声称已实现分级。
2. 现有演示策略允许上限内固定联系人即时模拟；新转账/安全稿有分级、延迟与规则累计上限。缺的是有依据的路由和执行状态机，不是简单把所有转账硬改为500元。
3. CM-C08要求先止损后补验与同设备秒解；当前CA06统一先认证。安全稿“已修”是资料里的陈述，不是当前代码通过证据。
4. F2的原生Android机制不适用于当前Web；E1优先级在正文与排期不一致，分别登记，不默认为额外必做范围。
