# 十稿场景、数据与功能同步落地 · 最小实施方案 V2

**交付的是完整下一版方案，不是本轮已完成的业务。原十稿、旧226项及现有代码均保留。**

## 先看结论

本版按“原文要求/人物与情境 → 场景数据 → 用户可见最小功能 → 现有代码最小改动 → 场景验收”重写。不是只补路演，也不是只抽工具接口。画像、支柱、红线、创新、功能覆盖与完整故事同时纳入；候选、储备、生产依赖则明确分开。

**新编号只用于本版。旧1–20成果复用，不当成全部未实现；旧21以后的编号不再作为施工顺序。** 当前代码快照 `4689188140299059ba324720726bb33ba266bad8`，状态说明以静态代码/历史明确记录为依据，本轮不重新声称浏览器、真人语音或真实银行业务通过。

## 采用优先级与投入边界

1. 第一档：账单、订阅、转账、理财、卡片，加竞品中与本项目对应的能力。场景内部必须的账单→订阅等接力随第一档完成，不等第二档。行为理论轻量嵌入，不另建大模块。
2. 第二档：独立跨场景事件/规则/人生事件日历/生日旗舰与外部生态准备。
3. 第三档：三方合成联邦风险实验与有界只读多Agent辩论，先证明比简单基线好。
4. 第四档：低成本攻防演示。既有授权、司法限制、适当性、确认和幂等是所有档位的基本验收条件，不能等第四档才有。

按当前Web/React/TypeScript、现有workflow/plan结构增量扩展，不为照搬原稿架构新建Rust/gRPC/图数据库。金融计算用整数分，模型只理解/解释；官方问卷、银行、征信、商户及App能力没有已验证来源时，明确合成或未接入。

**成本不是排期承诺**：单工程师熟悉现有React/TS沙箱的粗估；S≤0.5人日，M约0.5–2，L>2或专项；不含真实外部接入、正式动画、真人语音；共享工作不得逐行相加。收益=场景完整度/可见演示/复用；改造风险=资金、权限、数据来源与现有路径变更风险，不等于技术难度。

## 一次快速审核怎么用

先看[一页集中审核清单](quick-review.md)，核对每个画像、支柱、创新、红线的去向，再按完整场景选开发批次。不能用`first_batch`标记机械截前20项，那些只是分域建议，不是依赖闭合的工单。

推荐从账单—订阅完整闭环切入，并把三个画像的数据与分支同时接入。具体批次按[共用能力与依赖](shared-and-dependencies.md)排序；不为“凑20条”截断确认、结果观察或拒绝分支。其余第一档场景各自整场验收，独立生日旗舰仍属第二档。

审核入口建议（尚未开发）：同一页选画像/情境，显示原文依据、初始数据、逐步确认、实际沙箱结果与拒绝/改口/失败/重复请求，最后一次汇总结果。现有review-lite可扩展，不另建测试平台。

**本轮只交齐方案与静态复核，不开发审核页，不生成正式帧，不连接外部机构；不自动批准191项开工。**
