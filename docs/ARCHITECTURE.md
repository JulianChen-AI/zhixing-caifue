依据理财v1.5 §6.1及其他采用稿的五层设计：

```text
语音/文本 → 对话编排：意图理解 → 补信息 → 任务规划
                           ↓
                 确定性护栏：授权、确认、风险与适当性
                           ↓
                 工具适配：查询、受控写入、结果核验
                           ↓
                 数据层：业务记录、授权、任务和回执
                           ↓
                 结果解释与后续操作
                           ↓
      呈现层：React + TypeScript管理界面与Agent状态
                           ↓
                 状态→动作映射 → PixiJS播放PNG序列帧
```

这描述已选定的目标架构，不能证明组件已接通。LLM负责规划与表达，确定性逻辑决定操作是否获准；React中的展示状态来自业务事实，PixiJS消费动作选择，不执行资金或卡片操作。

| 部分 | 职责 | 交付或边界 |
|---|---|---|
| Sprite Studio + Codex | 动作制作、导出准备与资源核对 | 离线制作；交付PNG帧及动作清单，工具版本和具体导出流程待制作前核验 |
| React + TypeScript | 界面、交互、Agent展示状态与动作映射 | 金额、图表、认证、按钮和回执独立渲染；业务授权仍由确定性逻辑落实 |

| Web与后续移动端H5 | 复用动作资源和状态语义 | 分别验证尺寸适配、触控、页面恢复与加载表现；尚无H5验收结论 |

## 状态与呈现职责

典型展示状态是 `idle → listening → thinking → speaking → waiting_confirm → executing → success/failure`。流程可追问、取消、超时或回到等待；它不是已实现的状态枚举或全部业务的唯一顺序。

| 业务事件 | 角色与UI行为 | 完成判断 |
|---|---|---|
| 接收需求、补信息 | 倾听/思考，展示待补字段 | 信息完整不代表授权 |
| 等待授权或确认 | 等待动作，UI展示对象、金额、后果及认证入口 | 规定的确认完成 |
| 工具提交或异步处理中 | 执行动作，UI显示实际进度 | 受理/处理中不能报成功 |
| 可核实的成功结果 | 成功动作与真实/沙箱回执 | 按对应操作判定，不扩大为整个目标全部完成 |
| 失败、取消或状态不明 | 失败/安抚/待核验提示 | 禁止成功呈现，提供核验与下一步 |

动画播完、模型说“办好了”或展示历史回执都不构成新的执行结果。重播动画不重执行业务。改口、重复提交、迟到结果与取消竞争的处理须在正式桥接设计中明确。

## React、TypeScript与PixiJS接入边界

业务编排输出可核实状态，React + TypeScript维护当前任务的展示状态，映射层选择动作ID和播放参数，PixiJS负责帧播放。`idle → listening → thinking → speaking → waiting_confirm → executing → success/failure`是目标展示语义，接入时须与现有应用状态机核对，不能声称已存在同名API或枚举。

React负责播放器的挂载、卸载及业务级切换；逐帧推进由播放器处理。资源FPS与浏览器刷新率分开；换动作重置对应播放进度，重复状态不应无故反复重启。任务归属、事件去重、优先级、打断和迟到结果的字段及规则仍待接口设计；播放回调不得回写成功业务结果。

正式接入还需明确资源目录、动作清单、预加载范围、加载失败的静态兜底、页面隐藏/恢复及资源释放。加载失败不隐藏真实业务结果、不重执行业务。后续H5复用PNG和动作语义，适配布局、触控与资源预算后再验收。本轮不安装依赖、不修改现有应用代码、不建立播放器。
