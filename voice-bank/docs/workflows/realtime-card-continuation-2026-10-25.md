# 页面认证后的实时对话接续

## 已复现的原因

使用独立合成会话、真实 Qwen WebRTC、静音测试音轨及文字输入，完成演示债券基金确认与页面认证后，抓到提供方错误：`Cannot continue a cancelled tool turn; submit new input`。认证已经生成一笔 pending 订单，语音连接却随后退出；再输入冻结要求可能进入普通文字演示入口。因此，只检查最终银行卡状态会产生“真实模型全部通过”的假象。

复现记录：`outputs/live-final-2026-10-24T16-48-16-435Z/report.json`。没有读取其他用户或朋友的历史会话。该证据能解释一种认证后无法继续的故障，不能断言朋友遇到的所有情况都属于此原因。

事件顺序是：工具结果返回 → 请求模型续答 → 页面认证成功 → 取消旧回复 → 更新会话事实 → 没有新输入就再次请求续答 → 提供方拒绝，前端关闭连接。会话配置更新并不是新的用户输入。官方协议参见 [Qwen 实时客户端事件](https://www.alibabacloud.com/help/en/model-studio/client-events)。

## 修复行为

- 页面操作后显示后台实际结果，并同步模型事实；保持连接，等待下一次实际用户输入，不对已经取消的工具轮次自动续答。
- 页面事实同步不会生成用户话语、确认授权或虚构工具结果。下一句话仍使用同一个实时连接及最新业务状态。
- 页面更新只屏蔽过时输出；当前轮次自然结束后才发送最新会话配置，等待配置确认后才开始下一次模型回复。旧回复不能执行迟到的工具调用，用户主动插话仍能打断。同一回复的取消事件只发送一次。
- 已观察到回复期间更新配置后，配置虽被确认，旧回复却迟迟没有结束事件，前端一直等待。将新文字排队等待旧轮次的尝试没有稳定解决问题，因此最终保留即时用户输入，改为延后配置同步。不能仅凭这些轨迹断言所有反复确认都由同一原因引起。
- 提供方也曾仅返回开始调用工具的事件，45秒内没有完整参数：`outputs/live-final-2026-10-24T17-18-21-139Z/report.json`。新增30秒无进展超时，正常流式进展会延长等待；超时明确提示并停止连接、释放媒体，保留业务卡片，不猜参数、不自动重试交易。超时处理不代表提供方生成能力已经修好。

## 回归方法

- 协议回归覆盖配置确认与取消完成的两种顺序、尚未开始的旧回复、迟到工具、下一次真实输入恢复。
- `tests/browser/live-final-confirmation.cjs` 是主动运行的真实模型探针，需要配置 `BANK_TEST_URL`，会使用模型额度。它在新建合成会话中验证：债券确认 → 页面认证 → 等待结果 → 同会话冻结 → 页面认证 → 保持实时连接。必须观察到真实模型的冻结工具请求；回退文字入口不能算通过。
- 探针检查实际订单仅一笔、银行卡冻结、提供方错误及结束后的媒体连接清理。它不使用真人麦克风，不验证 ASR 准确率。具体运行结果保存在各次 `outputs/live-final-*/report.json`，不能用协议或手填工具测试替代模型结果。
- 候选版本在本地业务数据库上通过真实提供方的债券与冻结接续，记录 `outputs/live-final-2026-10-24T17-16-25-486Z/report.json`。后续探针增加冻结认证后的银行卡状态查询，检查第三个任务仍由同一实时连接处理。模拟提供方的页面退出探针也覆盖超时后提示及媒体释放。
- 完整候选版本：158项回归、类型检查及构建通过；7组页面退出/提供方停滞场景通过（`outputs/live-exit-2026-10-24T17-25-30-932Z/report.json`）。真实提供方、本地隔离业务数据库的三段接续通过，4次原生工具请求、无提供方错误、没有回退演示入口（`outputs/live-final-2026-10-24T17-25-32-381Z/report.json`）。连接建立通过测试代理使用服务器的SDP接口，API密钥未复制到本地；不等同于上线后的业务接口验证。
