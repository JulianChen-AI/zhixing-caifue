# 流式语音与后台监督

正常会话直接播放 Omni 的原生 WebRTC 语音，不再整段录音后等待 Flash 批准。`onReviewReply` 的旧接口保留兼容测试；页面使用独立的 `onSuperviseReply` 与 `onReconcileReply`。

## 观察与暂停

- 观察端点 `/api/bank/supervise` 只读取后台事实，没有提交业务的入口。Flash 只能返回继续或附具体依据的暂停建议。
- 有新内容时约每秒刷新候选快照，完整句和回复结束触发检查；不再有 32 字门槛和每轮两次的限制。一次仅运行一个观察请求，等待项保存读取函数，前一个请求完成后、下一次实际发送前再取最新转写和事件。已发送输入固定不变，不逐字并发调用。
- 说到一半、正在调用工具、必要追问，以及背景草稿未完成，都不直接算漏办。问卷明确答案未保存只在完整回复结束后作确定性判断。
- 新用户输入使旧轮自动暂停/修复失效，但未检查事件与待验证事项继续保留。工具在途时不应用暂停意见；工具结果、错误和页面状态变化都会记录。服务端在推理前后检查 revision，过期疑点只进入下一份快照重新核实，不能直接执行。新增文字本身不会丢弃仍有依据的暂停意见。
- 观察模型单次上限 7 秒，客户端观察请求上限 9 秒；同一 HTTP 请求不重发，空闲失败最多补查一次。观察不可用不等于核对通过，前台正常语音继续流式播放。

### 持续跟踪与容量（2026-10-31 修订）

- 应用维护有序事件：用户最终原话、助手转写增量、回复结束、工具开始/成功/失败、后台事实刷新和核对结果。合并待提交快照不删除未检查事件。
- `checkedThrough` 仅在有效、非过期结果后推进；快照带独立的 `through` 与 `latest`。最多每批 20 条事件、事件约 7 KB，未纳入该批的事件留到下一批。
- 近期已经检查过的用户/工具/状态事件保留为独立 `contextEvents`（最多 16 条、约 4 KB），供同轮最终回复和旧事项核对继续引用，不重新算作积压。这样工具结果先被检查、语音稍后结束时，仍能证明本轮确实查过。
- `pending` 表示已检查但还需跟踪的用户要求，`problem` 表示已发现的疑点，二者与检查进度分开。Flash 必须逐项返回旧事项的核对结论；关闭事项引用较晚的真实 user/tool_result/state 事件编号，由后台直接提取原文短证据，不能引用助手自己声称“改好了”，也不要求模型重新复制整条 JSON。
- Flash 先返回“用户要求—助手声明—后台实际”的简短对照，事实依据允许结构化对象，安全序列化后保留判定。空白通过、遗漏旧事项、伪造或不合类型的证据引用均视为检查不可用，不推进检查位置。正常解释不要求业务查询；说到一半的中性等待语只记录待验证事项。
- 空闲失败最多再检查一次；连续失败显示核对不可用提示。当前最多保留 128 条未检查事件和 8 个未解决事项，达到上限停止语音输出并提示通过卡片继续，不静默淘汰关键事件。
- 事件和待验证事项在当前页面内存中保存，语音重连与上下文轮换复用；重置演示时清空，不跨页面刷新持久化。诊断只保存检查编号、耗时、结果状态、不可用原因码、积压数量和落后时长，不写入转写、业务字段或密钥。
- 观察请求允许 64 KB，并对实际读取字节数检查上限；业务写接口及确认、认证、幂等限制不变。工具/状态事件是有界摘要，最新业务事实仍由服务端重新读取。

本次定向验证：`npm test` 380/380、类型检查和构建通过；可控时钟模拟 0.5/2/5 秒慢响应，验证单请求、最新快照提交与事件保留，不是吞吐实测。浏览器受控验证 6 项通过，包含真实页面与音频播放、模拟 WebRTC/观察服务；不属于真人语音验收。

`tests/supervision-live-eval.ts` 以合成内存状态调用真实 Flash，覆盖改金额未保存、取消未生效、无查询结果报数、中性等待期间持续跟踪、用户撤回、实际保存后关闭旧事项及大状态证据引用；7/7 通过，最新少量样本约 1.5～2.4 秒。报告为 `outputs/continuous-supervision/flash-eval.json`，失败的早期尝试另行保留。曾发现模型复制整段状态导致证据超长，以及把核对依据返回为对象导致类型拒绝，均已补回归。它不证明所有语义都能检出，也不覆盖 Omni 漏调用后完整补办或真人 ASR。

真实语音复测曾遇到单项余额查询选错业务并被后台拒绝；原会话指令同时要求直接调用余额工具和所有业务先建 Plan，本次统一为“单项直接用业务工具，后台自动建 Plan；多项/比例才用 bank_plan create”。这是入口指令修正，不代表 #11 的全部工具契约问题已解决。失败记录位于 `outputs/continuous-supervision/voice-live-attempt*.json`。

最终 `tests/browser/supervision-live.cjs` 的自然余额查询、自然解释、受控暂停三项均通过；Omni/Flash 为真实服务，输入为键盘与静音合成麦克风。三个场景结束时均为 `checkedThrough === latest`、`pendingEvents=0`、`openIssues=0`，各保持单个 WebRTC 会话，无新增资金写入。观察请求的显式长度及分块传输 64 KB 上限检查均返回 413。报告见 `outputs/supervision-live.json` 和 `outputs/continuous-supervision/request-limits.json`。

## 核对与更正

- 发现具体疑点后先停止播放并取消该次生成，不使用会中止所有工具的用户打断方法。工具在途时不接纳旧暂停建议；请求取消也不代表已撤销业务。
- 播放一次 Tina 音色的短录音“稍等，我再核对一下刚才的信息。”。真实核对与录音同时进行，录音可由用户立即打断。录音由配置的 Omni WebRTC 生成，去除首尾空白后存为 24 kHz 单声道 WAV；可用 `scripts/record-correction-cue.cjs` 重新生成，需要本地代理、Chrome、Playwright 和 FFmpeg。
- 暂停后重新读取后台事实，再调用原有受约束的复核端点。观察疑点是数据，不是事实或授权；已有业务结果、字段证据、当前确认和页面认证仍由后台校验。
- 一轮只自动核对修正一次。更正后的语音继续流式播放并被观察；若仍发现具体问题则停止并提示查看卡片，不反复安抚或重做业务。
- 用户开始新一轮时停止提示音、丢弃迟到核对结果。正常恢复不会伪造新的用户输入。

## 验证入口与边界

- `npm run check`、`npm test`、`npm run build`。
- `node tests/browser/background-supervision.cjs`：真实页面与媒体播放、受控供应商事件，检查慢观察不挡播放、提示音完整播放、一次核对、用户插话和观察失效。
- `node tests/browser/supervision-live.cjs`：真实 Omni 与 Flash、静音合成麦克风。`controlled-pause` 是受控暂停建议注入，不能当成自然发现错误的证据。报告输出 `outputs/supervision-live.json`。

后台观察可能在错误已经被听到后才发现，也不能保证识别所有语义漏办。业务执行校验独立保留。上述测试不代表真人麦克风、口音、回声、移动端自动播放或真实银行接入验收。原生工具后的供应商生成超时仍由现有恢复机制处理，须与等待 Flash 分开记录。
