# 最后确认时模型与页面按钮同时卡住

用户补充：页面状态异常，疑似最后确认阶段，模型和手动按钮都无法推进。本轮只使用新建合成会话及可控故障注入，没有读取用户或朋友的历史会话。

## 已确认的缺口

1. 模型返回 `response.done` 后，客户端会清掉进展计时器；但该轮业务 HTTP 请求仍可能未完成。业务等待标记保持为真，确认和认证按钮因此长期禁用，原30秒模型超时没有覆盖此阶段。
2. 页面直接发出的业务请求没有请求截止时间。确认或认证响应不返回时，同样不能走到释放按钮的收尾。

使用真实 React 页面、可控提供方/HTTP 延迟和真实业务 reducer，旧版三个场景均复现超时不恢复：`outputs/final-lock-2026-10-24T17-48-36-107Z/report.json`。这是同类锁死条件的复现，不代表已经取得用户那次故障的完整因果轨迹。

## 修复

- 模型轮次结束但业务工具仍在等待时，保留30秒超时；超时停止连接、取消等待并释放按钮。迟到结果不能复活旧调用。
- 普通业务请求统一30秒截止。响应丢失后的结果保持“尚未确认”，只进行一次最多5秒的状态读取，不自动重发写操作。
- 模型停滞关闭后读取当前业务进度；若后台已经进入认证，显示实际认证卡片，不从旧确认重新办理。
- 正在办理时提供“停止等待并核对进度”。此操作停止本地等待和语音连接，读取后台事实，不承诺已撤回原操作，不重复提交交易。

## 线上复测发现的语音分段问题

`2e01796`线上页面的五种恢复场景通过，记录为`outputs/final-lock-2026-10-24T18-14-30-540Z/report.json`；测试通过`BANK_TEST_DIRECT=1`直连私人站点，HTTP和提供方为受控故障注入。

同轮真实ASR将首句确认拆为“确认申购当前这笔演示债券基金一百元。”和“当前摘要继续。”。第二段在第一段ASR完成前已经开始，后续工具只携带第二段原话，被后台以“需要用户对当前摘要明确确认”拒绝。记录为`outputs/live-final-2026-10-24T18-13-19-875Z/report.json`。这不是工具JSON格式错误；不能通过放宽后台确认规则解决。

补充修复仅将相隔不超过1.2秒、在任何模型回复或工具调用前发生的语音段关联起来。只有前段明确确认、后段属于“按当前摘要继续”等窄范围补句时，工具原话才携带两段实际识别结果。新的业务、改口、否定、页面操作、模型已回复或较长间隔均不能借用前段确认。补充3项回归，合计162项通过；重放了此次ASR完成事件乱序，并覆盖禁止跨回复/页面/否定/修改/时间边界借用授权。

后续快速语音确认还复现了提供方控制事件`Response request cancelled by new input`：新语音取消旧工具续答，前端却将其按一般错误断连。记录为`outputs/live-final-2026-10-24T18-21-09-436Z/report.json`。修复仅识别这一精确的`invalid_request_error`消息及原有`response_cancel_not_active`；前者清理旧续答请求标记，保留新语音轮次。未知错误、权限、额度和其他取消工具错误仍按故障处理。新增协议和页面中断回归，合计163项协议/业务回归通过。

## 明确指令的执行保证

真实模型还有口头引导认证但不调用确认工具的情况（`outputs/live-final-2026-10-24T18-26-43-382Z/report.json`），后续查卡也曾只生成无关回复而没有查询（`outputs/live-final-2026-10-24T18-37-40-751Z/report.json`）。

最终增加窄范围明确指令入口：“确认/确认冻结/确认申购”等仅使用当前可见review的最新taskId和token，直接送原后台校验器，不能认证；“查看银行卡列表”等少量明确只读表达直接查询CA01。问句、否定、改口、目标操作不一致或复合指令不走此入口；复杂对话与草稿拆解仍由模型处理。重复ASR事件去重，插话会取消旧请求，迟到结果不得发布，不伪造提供方function_call_output。后台摘要、用户原话、风险条件、认证及幂等检查均保留。

报告按请求来源区分`model`、`literal-confirmation`、`literal-query`，不再将明确指令入口写成模型主动调用成功。168项回归与构建通过；7组最终锁定恢复通过（`outputs/final-lock-2026-10-24T18-44-05-988Z/report.json`）；8组退出/正常中断场景通过（`outputs/live-exit-2026-10-24T18-37-41-336Z/report.json`）。

本地业务库、真实Qwen/ASR的完整语音接续通过（`outputs/live-final-2026-10-24T18-44-06-192Z/report.json`）。这轮真实复现了债券确认被分两段后仍正确进入认证；冻结确认及查卡由明确指令入口执行。另有一笔模型多余确认被后台400拒绝，随后读状态恢复；没有重复订单或认证。通过结论只表示业务状态、明确指令及人工入口可推进，不能表述成模型从不多余调用或自然语义已全部可靠。
