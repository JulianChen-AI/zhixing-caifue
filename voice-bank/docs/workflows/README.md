## 文件与入口

- `lib/workflows/catalog-data.json`：54 个用户功能、85 组逻辑工具的设计目录。不是 85 个已开放的 HTTP 接口。
- `catalog.ts`：目录及不可用能力索引。
- `fields.ts`：逐功能参数白名单、入口缺项、候选列表和语音字段依据。
- `engine.ts`：收集 → 核对 → 确认 → 必要认证 → 执行/结果；支持修改、取消及恢复原任务。
- `adapters.ts`：确定性沙箱查询、计算、业务动作与执行前复查；异常操作整体回滚当前未提交副本。
- `seed.ts`：同一会话的合成流水、订阅、产品、目标、持仓、卡片及业务记录。
- `realtime.ts`：模型与页面分别允许的命令、紧凑工具结果；只提供Checklist需要的题目和已保存选项，不提供认证凭据或原始证据转录。
- `offline.ts`：离线演示的少量入口便捷分流；不参与原生 Omni 的日常语音理解。
- `components/workflow-panel.tsx`：功能选择、缺项表单、可选信息、确认、页面认证、结果、办理依据及未完成任务恢复。

新增原生工具 `bank_function`：`list / describe / run / amend / confirm / cancel / resume / status`。原 `bank_request` 六种 operation 保持兼容。模型输入金额以元计；后台资金始终整数分；回传模型转换为元并声明单位。

页面使用 `/api/bank` 的 `action:{type:"workflow",command:{...}}`。服务器绑定输入来源，不信任客户端提供的认证/通过标记。模型工具没有 `authenticate` 或 `settle` operation。专门页面认证使用演示码；`settle` 仅用于明确推进本会话合成订单，不连接真实市场。

`BI07 / BI10 / CA10 / CA11 / CA12` 明确返回未接入，不造结果。其余功能的 `sandbox` 只代表已有沙箱入口/基本适配路径，不表示文档每个参数、可选增强和所有 action 已完整实现。`describe` 返回当前 `acceptedFields`、`actions`；不支持的字段直接拒绝。复杂路径仍可能返回明确的未接入结果。

周期资金/定投规则目前只保存可查询、修改、暂停和取消的指令，**未启动自动扣款调度**。站内提醒规则也不代表已通过系统通知交付。所有创建结果会显示此边界。

## 可选参数和必要条件

- 创建转账时不传 `note`：无备注，标记备注整理步骤跳过；不主动追问。
- 修改时不传 `note`：保留已有备注；传 `null`：明确清空；传文本：按用户依据替换。
- `saveRecipient / autoSave / share` 等默认关闭；实际请求但工具缺失时说明限制，不假装完成，也不重跑已成功业务。
- 工具结果分别返回 `missing`、`requiredFields`、逐字段 `required`。只补必要缺项；未开启自动转存的目标无需关联账户或周期。
- 明确请求的导出、提醒、群体数据、预测等若未接入，通过 `limitations` 和页面“能力说明”单独展示；主业务完成不等于这些附加项也已完成。
- 缺少收款人、账户、金额可以先建草稿，执行前必须补齐。
- 规则、余额、适当性、确认和认证不能靠 `skipAuth / passed / safe` 之类模型参数绕过。
- 查询不执行交易式确认。写操作按当前动作确认；涉及资金/卡片等需要页面演示认证。
- 每次修改都换当前摘要令牌，撤销旧确认及认证；认证前重新读取当前事实检查。
- 模型确认必须同时具有当前 token 和当前明确用户确认，不能使用历史“确认”。
- 插话时旧工具输出不向已取消调用回传。若请求可能已提交，页面重新读取业务状态并同步事实；模型应先查询最新状态，不能假称回滚。
- 语音参数截断时仅接受供应商后续真实终态中的完整 JSON；仍不完整就不执行，并提示重试或页面办理。请求已经发出但结果不可读则按未知结果查询，不假称未提交。
- `preview` 仅代表待确认的计划或试算；`result` 才用于已返回的查询/操作结果。受理中的基金订单仍须等结算。

## 数据与错误恢复

新状态保存在原 `demo_sessions.state` 内，由原 revision 条件更新原子提交；无需新建数据库表。旧会话加载时补入合成业务数据，原转账和回执保留。

多个待办任务有独立 ID，查询或测评不会抹掉待购买任务，可通过 `resume` 恢复；没有动态后台规划模型。当前是预设参数化 checklist 执行层，后续组合计划可复用该层，不应宣称已实现自由规划器。

业务副作用先在副本上执行，失败不把部分余额/业务变更写回。成功请求有幂等记录；未知或超时状态先查询。申购和赎回先返回 pending，页面“推进模拟结算”才变更持仓或到账，撤单只针对 pending 订单。

## 验证方法

1. `npm run check`：类型检查。
2. `npm test`：当前共 96 项，包含原转账/清单/Realtime 回归和新增工作流、协议边界测试。
3. `npm run build`：生产构建。Windows 上需要先停止本仓库占用 dist 的旧 Wrangler/Workerd，再构建、重启预览；不要停止其他项目进程。
4. `node tests/browser/workflows.cjs`：本机 Chrome、手机尺寸、实际卡片操作、认证、持久化、过期令牌及模型认证接口拒绝；报告和截图存 `outputs/`。
5. `node tests/browser/live-workflows.cjs`：真实 Qwen WebRTC＋中文合成音频；需要现有本地服务配置及 `work/workflow-query.wav`。可按原聊天方法通过 Windows SAPI Huihui 生成“请查询二零二六年十月的餐饮支出”。包含语音查账及52元净支出口径、新工具、插话切业务、目标明确确认和结果回传。可设置 `BANK_TEST_RUN` 保留独立报告。

浏览器脚本支持 `BANK_TEST_URL / PLAYWRIGHT_MODULE / CHROME_PATH`。默认复用本机 Codex 配套 Playwright，不临时下载浏览器。合成音轨和键盘输入测试不等于真人手机麦克风、回声、听感或移动网络验证。
