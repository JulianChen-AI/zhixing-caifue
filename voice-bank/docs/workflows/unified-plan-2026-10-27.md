# 统一 Plan 与任务 Checklist

所有应用业务入口（语音工具、文字指令、页面选择）在 `/api/bank` 经过同一个 `dispatchAction`。单项业务也进入 Plan；多项请求先按完整原话拆解，再顺序办理。业务字段、证据、问卷选项和确认状态由后台保存。

## 实例与执行分开

创建 Plan 时，一次创建全部已明确业务的 `FlowTask`，将同一组 Task ID 写入 `Plan.taskIds`。业务条目的内部 `id` 与 `taskId` 相同，激活时沿用原任务实例。后续任务初始为 `queued`：可以保存用户明确提供的字段，但不会查业务数据、生成核对授权、认证或执行写操作。

轮到任务时，后台加载它的 Checklist。字段填齐只进入核对；实际完成后，后台检查 Plan、说明切换并进入下一任务。每项写业务分别确认和认证，不沿用上一项的用户确认。比例计算仍由后台在轮到该任务时读取余额；确认或认证前余额变化会重新计算、撤销旧授权并要求重新核对，Task ID 保持不变。

内部保留计算依据和依赖元数据，用于比例金额及旧会话兼容。它们不再要求模型维护另一套业务 Step ID。用途不明确的条目先澄清；不能删除不明确的业务来执行后面的写操作。

## 一个清单中的插入与恢复

- `bank_plan interrupt` 把新业务插入当前清单，不创建嵌套的临时 Plan。原任务和已填字段保留。
- 实际完成或取消插入项后，后台继续下一项；被明确暂停的原任务保持暂停。
- 未完成的任务可以按原 Task ID 重新选中，后台调整待办顺序，并检查依赖及认证状态。等待认证时不能切到另一任务。
- 单项取消只取消该任务；整张清单取消需要明确取消全部剩余任务。已受理或完成的业务不会因取消对话而撤回。
- 模型工具不再要求 `planId` 或 `stepId`。当前任务的补充、查看及恢复省略 Task ID 时由后台绑定；指定另一任务时只引用它的 Task ID。旧字段仍兼容，但明确传错 ID 会拒绝。
- 旧嵌套 Plan 在读取/修改时合并为一个清单，保留原任务 ID、字段和执行结果。不会重新运行完成的历史任务。
- 待办实例最多 20 项；已完成清单及任务历史有界保存，保留未完成比例任务所需的计算依据。

状态继续使用现有会话 D1 JSON 与 revision CAS，无数据库迁移；通知、字段和调度一起保存。重复 requestId 不重复执行。旧版本尚未进入 Plan 的草稿可按原 Task ID 纳入清单，不重建问卷。

## Flash 复核

明确恢复请求先匹配后台唯一已保存任务。其他工具失败或口头进度未落库时，Flash 依据本轮原话、Checklist、实际错误及任务状态提出一次草稿操作。它可以建立草稿、填字段或恢复任务，不能确认、认证或执行写业务。

本次也修正了自动工具调用达到上限时漏掉复核的路径：六次调用后停止实时模型的自动重试，再进行一次复核。复核结果更新卡片和实际事实，等待新用户输入，不重开自动调用循环。模型之间的一致意见不能替代用户授权或字段证据。

## 验证与已知限制

- 255 项自动测试、TypeScript 检查通过。覆盖提前建立实例但不执行、后续字段及证据保存、原 ID 激活、跨任务确认隔离、单项取消、旧会话迁移和调用上限处的一次性复核。
- 连续 100 次查询插入及序列化重载后，原问卷 ID、已选答案和未提交状态保留，最后明确确认只生成一条记录。
- 页面回归通过：三项任务 → 保存第一题 → 临时查卡自动返回 → 重载 → 插入储蓄目标草稿 → 页面切回测评并保留目标 → 取消未提交目标 → 补齐并确认 → 自动查询末项订阅。
- 真实模型确认接续通过：工具先保存用户明确的三题答案并进入核对阶段，随后 RealTime 使用原任务确认，后台自动完成订阅查询，模型播报测评和订阅结果。
- 真实模型的 44 轮场景本次在第 3 轮失败：用户要求开始测评，RealTime 只口头答应而没有调用工具，Flash 又尝试恢复已完成的测评记录查询。后台拒绝，没有创建问卷或提交业务。这不是 Plan ID 丢失，也不能据此认定上下文溢出。
- 另一组 8 轮真实场景在第 4 轮因实时连接关闭而停止；前三轮完成建清单、保存第一题及临时查卡返回，Plan/Task ID 保持一致。这次也不算通过。
- 中间版本的 8 轮真实场景中，模型把账单查询错选为 IN08，拒绝后反复重试；原答案保留。省略 Plan ID 已不再是阻断原因。另修正了原文包含“最后”等顺序词时，合法任务引文被过严匹配拒绝的问题。
- 真实模型仍可能漏调用、错选业务或给出错误复核参数；实例与调度简化没有解决全部模型可靠性问题。连续长对话不能标为通过。

测试使用隔离合成会话、相同应用调度器/reducer，以及真实 Qwen RealTime/Flash 服务。页面检查本身不调用模型；真实测试通过键盘进入 WebRTC 会话，不包含真人麦克风/ASR，也不是线上 D1 持久性验收。没有部署或修改现有站点数据。
