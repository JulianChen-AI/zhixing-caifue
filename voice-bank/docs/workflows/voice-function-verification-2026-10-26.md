# AA语音工具调用修复与实测（2026-10-26）

## 已修复

1. `bank_function` 公开各功能的实际字段、类型及动作，AA明确使用 `TR05`、`total`、`participants`名单；不再诱导模型把人数当名单、把`amount`当AA总额。
2. 待补充/待核对工具结果提供原任务的 `amendRequest`，补名单和改口必须实际更新卡片，不能只口头说“填好了”。
3. AA总额与人均分开校验；数字“3个人”不当3元；沿用已收集名单，不虚构新增成员。未确认的名单只在草稿阶段转为待补充，清空名单、使旧确认失效；不执行AA。结构错误、未知字段仍拒绝。
4. 查AA记录用`TR05 action=list`，单条状态才用带既有ID的`status`；不改查转账。产品等ID必须从目录/候选原样取，不能猜`cash`/`bond`。

## 可重跑命令

在本应用目录运行：

- `npm run verify:voice:tools`：离线确定性回归，不调用外部模型。
- `SMOKE_GROUP=all npm run verify:voice:live`：真实Qwen，AA连续流程及五类读取；会产生真实服务调用。
- `SMOKE_GROUP=read npm run verify:voice:live`：只测五类只读工具调用。
- `SCENARIO=baseline npm run verify:voice:live`：复跑原始同一句，只记录实际状态，不能只凭completed字样判通过。
- `SCENARIO=audio npm run verify:voice:live`：合成音频与严格转写断言，原失败测试保留。
- `SCENARIO=audio-safe npm run verify:voice:live`：重放已保存WAV检验安全出卡，单列名字是否准确。依赖辅助目录中的原WAV，不会把错字标成准确。

默认本地服务为http://127.0.0.1:5180，需要项目已有Qwen配置；不要把密钥写入命令或聊天。系统无Tingting时，本轮实际用Meijia(zh_TW)合成，未下载新声音。
