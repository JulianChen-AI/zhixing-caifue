# 未执行转账草稿的取消与暂停建议保留

Issue #14 的本次复现：用户说“不转了”，Omni 只口头答应，没有调用取消工具；后台仍为 `review`，卡片仍可确认转账。另一个问题是 Flash 检查旧回复时，同一用户轮次已切换到新回复，暂停建议被丢弃。

## 本次修改

- 在用户首次输入时记录当前任务 ID；复核只能按本轮明确原话取消同一份当前未执行草稿。支持“不转了”“取消当前这笔转账”等明确表达；否定、问句、另一个任务、已完成转账不进入此路径。保留原有冻结草稿的明确取消入口。
- 后台复核直接使用受校验的取消动作及已有状态机。Flash 的通用补救动作白名单仍不包含取消、确认或认证；模型意见本身不构成执行授权。
- 当前回复结束时，如果原草稿尚未按明确要求取消，产生只读暂停建议；执行复核重新读取最新状态并保存取消，页面使用返回的真实状态更新卡片。
- 同一用户轮次的暂停建议跨回复保留。工具执行、上下文同步期间先等待，完成后重核；新用户输入或会话结束会清除旧建议。
- 有效暂停建议不因附带的旧事项解决记录不合格而丢失。不合格记录不关闭事项、不推进已检查位置、不成为操作证据；暂停后仍须读取后台事实。

## 验证

- TypeScript 检查、生产构建通过；398/398 自动测试通过。
- 最终版本使用真实 Omni WebRTC 和真实 Flash，在两个独立浏览器会话完成：转 200 元 → 选择室友张三及日常账户 → 改 300 元 → 不转了。8/8 步的后台状态、卡片、原任务 ID、余额及回执检查通过。
- 普通会话正常取消。故障会话真实中断两次原生取消 HTTP 请求，随后 `/api/bank/review` 返回 `toolAttempted: true`，将原任务保存为 `cancelled`；卡片显示“已取消”，余额不变、转账回执为零。
- 此前额外一次真实会话再次自然出现“不调用取消工具、只口头答应”，也由后台补救取消成功。
- 最终详细证据：`outputs/pr14-cancel-final-20261031/normal/report.json`、`outputs/pr14-cancel-final-20261031/fault/report.json`，同目录含逐轮截图。

上述实时测试用键盘触发语音会话和静音虚拟麦克风，没有验证真人麦克风／ASR。故障会话最终语音仍使用“那就不管它了”的含糊措辞，卡片及后台已取消；本次不能据此宣称语音表达完全稳定，或 Issue #14 的所有业务均已修复。异步核对也不保证错误语音在被发现前完全没有播出。

## 重跑

本地应用运行并配置真实模型后，在 `voice-bank` 目录执行 `npm run verify:cancel:live`。默认使用 `http://127.0.0.1:5180`，结果保存到 `outputs/cancellation-live/`。可用 `BANK_TEST_URL`、`BANK_TEST_OUTPUT`、`CHROME_PATH`、`PLAYWRIGHT_MODULE` 指定环境。

设置 `FAIL_NATIVE_CANCEL=1` 可中断原生取消请求；该模式还检查后台复核确实执行取消。没有模型和业务回执替身；故障注入只中断原生取消 HTTP 请求，复核端点仍真实执行。
