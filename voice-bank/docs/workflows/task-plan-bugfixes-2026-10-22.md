# 双层清单边界问题修复

日期：2026-10-22。基于本地 `1e4bc20` 的双层任务实现，修复位于 `fix/live-page-close`；未推送或部署。

## 复现与修复

以下问题先通过回归测试复现，再修改执行器。原有19项计划测试通过时，这些边界仍会失败。

| 问题 | 复现条件 | 修复后的行为 |
| --- | --- | --- |
| 修改会解除暂停 | 暂停两笔转账，再通过计划接口修改第二笔金额 | 保存修改并保留暂停；明确恢复后才继续，第二笔仍等待第一笔完成 |
| 改备注丢失计算关联 | 比例金额4288.33元不变，补充备注并重述同一金额 | 保留余额比例绑定；只有实际修改金额、账户或业务类型才解除绑定 |
| 旧发言可授权后续摘要 | 三笔转账，在第三笔复用第一笔确认、创建任务或改金额时的turnId | 保存摘要相关轮次和已使用确认与摘要的对应关系；旧发言不能授权另一步或改过的摘要，刷新后仍有效；同一摘要的重复确认不重置认证 |
| 重算异常没有保存停止状态 | 已确认三分之一转账，余额变成1分，再认证 | 保存计算失败，撤销旧子任务及原转账认证，停止后续；余额恢复后可继续，已完成读取不重做；余额变为相同时返回账户选择 |
| 否定取消会被执行 | 模型调用cancel，原话为“不用取消”“不必取消”或“不要不办了” | 外层拒绝否定取消；普通内层业务也补充“不必取消”的拦截，草稿保留 |
| 比例数字被截取 | 0.001%、.5%、3.1分之一、三分之一点五、负三分之一、1/3e2 | 先检查完整数字表达，不截取合法后缀作为不同金额；明确拒绝并要求澄清。支持正整数分数及最多两位小数的百分比 |
| 重算金额来源被误记 | 余额变化后由后台重新生成金额和账户 | amount/accountId仍标记为calculation并指向外层计算步骤，不会记录为没有原话的utterance |

本次不新增模型或资金执行器。计划仍调用原内层清单，每项写操作分别核对、确认及页面认证，已完成步骤不回放。
